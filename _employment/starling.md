## Responsibilities
- Shaped onboarding API requirements directly with partner clients, product and compliance teams
- Adapted onboarding and reverification flows for BaaS clients, aligning with core systems owned by other engineering teams
- Wrote and maintained API documentation for client integrations, working with technical writers
- Built transaction freezes to support urgent fraud investigations
- Took part in incident response, releases and production support

## Key contributions
- Designed a flexible domain model for the SaaS template, covering core banking functions, account structures and international addresses
- Redesigned fraud rules around how investigators actually work, so they could create and adjust rules in a portal without engineers or releases. Consolidated duplicate rules and removed over half of the stored rule data
- Spotted an ID-verification flaw that would break once external clients called endpoints directly and the bank accepted more international IDs. Drove the code and database fix with the owning team
- Asked what problem internal tools needed to solve before building, adding small UX wins such as inline snippets, filters and date searches that cut tab-switching for investigators
- Spotted recurring design issues, such as tightly coupled services and overlapping domain models, and proposed fixes for long-term maintainability
- Wrote onboarding guides that helped new engineers become independent sooner
- Informally mentored newer women engineers, and co-chaired the Race & Ethnicity Network

## What I gained
- Designing APIs and domain models for external clients in a regulated environment
- Balancing urgent operational needs against long-term design
- Confidence working directly with clients and non-technical teams
- An understanding of how fraud, compliance and operations shape technical decisions
- Seeing how good documentation makes a team more reliable
